# Notes for Claude

Captain's Game Engine (CGE), LGPL 2.1. The engine library is `Engine/`; the other folders are projects built on it (Adventure, editor, OSMRacer, torchdelve) and its unit tests (`tests/`).

## Plans and records
- The plans for the engine's changes and the status of every step (what was done, what was checked and how, what wasn't, and "Worth knowing" notes) are kept outside this repository, with the projects that drive them. **`CLAUDE.local.md`** (next to this file, not in git) says where. Read the step you're working on there, and record a finished step there, not here.
- **Nothing in this repository names those projects** (code, comments, CMake, README, these notes): they are private. Notes about them go into `CLAUDE.local.md`.
- Existing projects keep working by being ported, not by keeping old APIs. Every change is checked against all projects (the regression check below).
- Don't commit or push unless asked.

## Code style
- Match the surrounding file: `//!` Doxygen comments on declarations, `//` comments starting lowercase and saying why, `{` on the same line, two-space indentation, `name_` members in newer code.
- Some files have CRLF line endings, others LF: keep each file's endings (check with `file`; the Edit tool keeps them, scripts must too).
- Platforms: `#if defined(WIN32)`, `LINUX` (X11), `ANDROID` and `__EMSCRIPTEN__`. The web defines `UNIX` but not `LINUX`, and the engine is a static library there; elsewhere it's a shared library (`CGE_API`, `cge_export.h`).
- Where things are: the windows per platform are `window/native*.cpp` (`nativeLinux` is X11; the X11 event loop is `Engine::processEvents` in `system/engine.cpp`); input is `input/`; the platform services (clipboard, cursors, text input, URLs, importing and exporting files, settings, user folders, assets) are `platform/`, with the table of what exists where in `platform/services.h` and engine-internal hooks in `platform/platform_internal.h`; the ImGui backends are `ui/imgui_impl_cge_*` (ImGui in `extern/imgui` is the docking branch, with the engine's `imconfig.h`); the renderer is `renderer/` with the GL backend in `renderer/GL`; 3D models are `mesh/` (`Mesh`, `Model`, and `ModelFile`, which reads glTF with cgltf from `extern/cgltf`; the node hierarchy is `renderer/scenenode.h`; the glTF test files are written by `tests/data/make_fixtures.py`); text is `renderer/font.h` (FreeType through the `SpriteBatch`) and `renderer/screentext.h` (the old print queue, `Engine::getScreenText`), the system font lookup `platform/systemfonts.h`, screen transitions (fade, rectangle, circle, shutters, clock, blend; used by the Adventure's screen changes) `renderer/screentransition.h`, particles (`renderer/particles.h`, drawn through the `SpriteBatch`; used by the Adventure's weather particles; `Adventure/AdvEngine/test/make_particletest.py` makes a test game), and the engine's fonts are `Engine/fonts/`. Audio is `audio/` (miniaudio; `audio_internal.h` keeps miniaudio out of the public headers); video is `video/` (pl_mpeg and libtheora; `CGE::Video` plays, `CGE::VideoDecoder` decodes). The StoryDesigner is `Adventure/Designer` (the target `Designer`, the program `StoryDesigner`; it replaced a C# program whose project files `model/` reads and writes byte for byte, checked against its output in `tests/data`; `model/pcdkparser.cpp` is the C# editor's script parser for completion and the language list, `model/scriptcheck.cpp` checks scripts with the game's ANTLR grammar and Lua, `model/stateframes.cpp` is the states and frames of items, objects, characters and the cursor, `model/images.cpp` finds a project's images (their path, next to the project, an unpacked `.adz`'s folders, `gfx.dat`), `model/roomedit.cpp` is the room editor's rules (placing, depth order, walkmap, depth map, inventory field, FX shapes), `model/resources.cpp` the pools' resources (new, rename, duplicate, delete, folders, adding media), `model/bitmapfont.cpp` the game's bitmap fonts (FreeType, as the C# editor's GDI+), `model/gamefile.cpp` Create game, the `.adz` export and its unpacking, and the character and room imports; `app/` is the ImGui window, `app/stateframeeditor.cpp` the state and frame editor, `app/roomeditor.cpp` the room editor, `app/gamewindows.cpp` the fonts window, the media preview, Create game and Run game, `app/process.cpp` starts the game and the video converter, `app/toolwindows.cpp` the About window and the remote control of a running game, `app/i18n.cpp` its German texts; `data/font.dat` is the games' own font); its video converter is `Adventure/Designer/videoconv` (Windows; a 32-bit ExternalProject with Visual Studio). The Android activity's Java code is `Engine/android/java` (`CgeActivity`, `TextInputView`); `CgeActivity` also runs the document picker for `Platform::importFile` and `exportFile`; the web shell page is `Engine/web/shell.html`. Torchdelve is `torchdelve/` (`TDClient`, `TDServer`, `TDEditor`, which compiles the quests' `.map` files with the editor's `editor/tdmExport.cpp`; `torchdelve/tools` makes its quests and art; `torchdelve/README.txt` is the manual).

## Building
Release builds; the presets are in `CMakePresets.json`, the machine-specific ones (`windows-local`, `android-local`) in `CMakeUserPresets.json`, which git ignores. Logs go to `build/*.log`, named by step (e.g. `build_1c5.log`); grep them for `warning|error`.

| What | Command |
|---|---|
| Windows, all projects | `cmake --build --preset windows-local` |
| Tests, Windows | `ctest --preset windows-local` |
| Install (Windows) | `cmake --install build/windows-local --config Release` (into `build/install/windows-local`; the Adventure demo and the editor are run from there) |
| Linux (WSL), all projects | `wsl -e bash -lc "cd /mnt/c/Projects/captainsengine && cmake --build build/default -j8"` |
| Tests, Linux | `wsl -e bash -lc "cd /mnt/c/Projects/captainsengine && ctest --test-dir build/default"` |
| Web | PowerShell: `. C:\Projects\emsdk\emsdk_env.ps1; cmake --build build/emscripten` (and `build/emscripten-threads`) |
| Android | `cmake --build --preset android-local` (configured with `-DPROJECT_OSMRACER=OFF`, a desktop program; the editor and Torchdelve are off on Android and the web by default) |
| Adventure APKs | PowerShell, in `Adventure/android`: `$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"; .\gradlew.bat assembleDebug` (flavors `player` and `game`, see the README) |

**Regression check** (expected for every step): the Windows build of all projects with no errors and no warnings; the Linux build with only the known warning (`tmpnam` in the vendored Lua); the unit tests passing on Windows and Linux (322 on Linux as of 2026-11-27, 43 of them the StoryDesigner's; one more, `ModelFiles.SampleModelsLoadOrSayWhy`, is skipped unless `CGE_GLTF_SAMPLES` names a folder of glTF models, e.g. Khronos' glTF-Sample-Assets `Models`); no new warnings on the web and Android; and the projects a change touches started and tried (the Adventure demo, the editor, Torchdelve (after `python torchdelve/tools/install_pack.py <install folder>`: `TDServer 28405` from `TDServer`, then `TDClient` from `TDClient`, connect to 127.0.0.1:28405, log in as captain, load basic/lamplighterTest: the quest text appears over the board), and the games built on the engine that `CLAUDE.local.md` lists).

Built as part of a game (`add_subdirectory`, `CGE_DIR`), the engine's own projects and tests are switched off.

## Testing on the platforms
- **Windows:** drive applications with PowerShell (`SendInput`/`mouse_event`; VK keys need their scan code from `MapVirtualKey`, `KEYEVENTF_UNICODE` types any character), screenshot with `System.Drawing` `CopyFromScreen` (after `SetProcessDPIAware`), use `Get-Clipboard`/`Set-Clipboard`. `SendKeys` goes to whatever has the focus.
- **Linux:** WSLg. Drive with `xdotool` (the engine's X11 window is found by `--name "Captains Game Engine"`, not by `--pid`). WSLg windows are Windows windows, so screenshots come from PowerShell's `CopyFromScreen` when the window is in front; when other windows cover it (`PrintWindow` gives black), a small X11 client that saves `XGetImage` of the window as PPM does it. WSLg bridges the X11 CLIPBOARD to Windows' clipboard, but only for the focused client. `sudo` needs a password, so nothing can be installed with apt from a session; small test X11 clients build with `g++ ... -lX11`.
- **Web:** a Node script drives headless Chrome (mouse, touch, keys, input-method text, screenshots); `CLAUDE.local.md` says where it is. A debug build (`CMAKE_BUILD_TYPE=Debug`, `-sASSERTIONS=2`) gives function names in stack traces; `emsymbolizer <file>.wasm <address>` gives the source line.
- **Android:** the emulator `Medium_Phone_API_37.0` (x86_64), through the Adventure's Gradle project (`Adventure/android`; the game APK `de.captain_online.adventure.demo` has the demo, the player `de.captain_online.adventure` adds games with the system's file picker, which `uiautomator dump` and taps on the found texts drive). Logs: `adb logcat -s CGE`, crashes `adb logcat -b crash`. In the Adventure, Ctrl+R (`adb shell input keycombination KEYCODE_CTRL_LEFT KEYCODE_R`) restarts the render device; `run-as <app id> ls files/bin` shows the demo's saves.
- **Audio:** the unit tests mix without a device (`Audio::Desc::device = false`, `Audio::render`). What the applications really play: a WASAPI loopback recorder of Windows' output, which also carries WSLg's Linux sound and the Android emulator's, and a script that prints the levels over time (`CLAUDE.local.md` says where both are). In the browser, an `AnalyserNode` on miniaudio's `scriptNode`.
